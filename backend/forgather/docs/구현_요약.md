### 1. `auth.js`에 `refreshToken()` 메서드 추가

**파일**: `/backend/forgather/src/main/resources/static/js/admin/auth.js`

**추가된 메서드**: `Auth.refreshToken()`

**목적**: Refresh Token을 사용하여 `/api/admin/refresh` 엔드포인트를 호출하고 새 Access Token 발급

**주요 기능**:
- 무한 루프 방지를 위해 직접 `fetch` 사용 (`API.request()` 사용 안 함)
- 401/404 에러 시 로그인 페이지로 리다이렉트
- 새 토큰을 localStorage에 자동 저장
- 흐름을 설명하는 상세한 JSDoc 주석

**코드 위치**: 141-220번 라인

```javascript
async refreshToken() {
    const refreshToken = this.getRefreshToken();

    if (!refreshToken) {
        console.warn('[Auth] Refresh Token이 없습니다. 로그인 페이지로 이동합니다.');
        this.clearTokens();
        this.redirectToLogin();
        throw new Error('No refresh token available');
    }

    // 직접 fetch 호출 (무한 루프 방지를 위해 API.request 사용 안 함)
    const response = await fetch('/api/admin/refresh', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },

    });

}
```

### 2. `api.js`에 401 인터셉터 추가

**파일**: `/backend/forgather/src/main/resources/static/js/admin/api.js`

**추가 기능**: `API.request()` 메서드에 401 에러 발생 시 자동 토큰 갱신 기능

**주요 구성요소**:

#### a. 토큰 갱신 Promise 캐시
**목적**: 여러 API 호출이 동시에 실패할 때 중복 갱신 요청 방지

**코드 위치**: 7-26번 라인

```javascript
let tokenRefreshPromise = null;
```

**동작 방식**:
- 첫 번째 401 에러가 `Auth.refreshToken()`을 트리거하고 Promise를 캐시
- 이후 401 에러들은 캐시된 Promise를 재사용 (같은 갱신을 대기)
- 갱신 완료 후 캐시를 `null`로 초기화

#### b. 향상된 `request()` 메서드
**목적**: 401 에러를 자동으로 감지하고 새 토큰으로 재시도

**코드 위치**: 63-173번 라인

**플로우**:
1. API 요청
2. 401 감지 시:
   - 재시도인지 확인 (무한 루프 방지)
   - `Auth.refreshToken()` 호출 (또는 캐시된 Promise 재사용)
   - Authorization 헤더를 새 토큰으로 업데이트
   - `isRetry=true` 플래그로 원래 요청 재시도
3. 재시도도 401 반환 시, 로그인 페이지로 리다이렉트 (Refresh Token 만료)

**핵심 로직**:
```javascript
async request(url, options = {}, isRetry = false) {
    const response = await fetch(url, options);

    if (response.status === 401) {
        if (isRetry) {
            // 재시도 중지, 로그인 페이지로 리다이렉트
            Auth.clearTokens();
            Auth.redirectToLogin();
            throw new Error('인증이 필요합니다. 다시 로그인해주세요.');
        }

        // 토큰 갱신 및 재시도
        if (!tokenRefreshPromise) {
            tokenRefreshPromise = Auth.refreshToken();
        }
        const newAccessToken = await tokenRefreshPromise;
        tokenRefreshPromise = null;

        // Authorization 헤더 업데이트
        options.headers['Authorization'] = `Bearer ${newAccessToken}`;

        // isRetry=true로 재시도
        return await this.request(url, options, true);
    }

    // 다른 상태 코드 처리...
}
```

## 동작 방식 (엔드 투 엔드 플로우)

### 시나리오: 사용자가 만료된 Access Token으로 Spaces 페이지 로드

```
1. 사용자가 /admin/spaces 페이지 열기
   ↓
2. spaces.js가 호출: await API.getSpaces(1, 15)
   ↓
3. API.get() → API.request() → fetch('/api/admin/spaces')
   ↓
4. 서버 응답: 401 Unauthorized (Access Token 만료)
   ↓
5. API.request()가 401 감지
   ↓
6. API.request()가 호출: Auth.refreshToken()
   ↓
7. Auth.refreshToken() → fetch('/api/admin/refresh', { refreshToken })
   ↓
8. 서버 응답: { accessToken: "new_token", refreshToken: "new_refresh" }
   ↓
9. Auth.refreshToken()이 새 토큰을 localStorage에 저장
   ↓
10. API.request()가 Authorization 헤더를 새 토큰으로 업데이트
   ↓
11. API.request()가 재시도: fetch('/api/admin/spaces') with new token
   ↓
12. 서버 응답: 200 OK with spaces data
   ↓
13. spaces.js가 데이터를 받아 테이블 렌더링
   ↓
14. 사용자는 spaces 목록 확인 (토큰이 갱신된 줄 모름!)
```

**사용자 경험**: 끊김 없음. 로그인 페이지로 리다이렉트 없음. 에러 메시지 없음. 그냥 작동함.

## 백엔드 요구사항

### Refresh Token API 구현 필요

**엔드포인트**: `POST /api/admin/refresh`

**요청**:
```json
{
  "refreshToken": "eyJhbGciOiJIUzI1NiIs..."
}
```

**성공 응답 (200 OK)**:
```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIs...",
  "refreshToken": "eyJhbGciOiJIUzI1NiIs..."  // Optional: 새 refresh token
}
```

**에러 응답**:
- `401 Unauthorized`: Refresh Token 만료/유효하지 않음 → 프론트엔드가 로그인 페이지로 리다이렉트
- `404 Not Found`: 사용자를 찾을 수 없음 → 프론트엔드가 로그인 페이지로 리다이렉트
- `500 Internal Server Error`: 서버 에러 → 프론트엔드가 에러 표시

**참고**: 프론트엔드 코드는 이 정확한 API 구조를 기대합니다. 백엔드 API가 다르면 조정이 필요할 수 있습니다.
