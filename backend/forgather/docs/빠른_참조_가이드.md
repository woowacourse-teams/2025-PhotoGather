# 자동 토큰 갱신 - 빠른 참조 카드

## 프론트엔드 개발자용

### 사용법 (핵심 요약)

**그냥 API 래퍼를 사용하세요. 토큰 갱신은 자동으로 처리됩니다.**

```javascript
// 이게 전부입니다! 401 에러를 처리할 필요가 없습니다.
try {
    const data = await API.getSpaces(page, size);
    renderSpaces(data);
} catch (error) {
    showError(error.message);
}
```

### 새 API 호출 추가하기

```javascript
// api.js에서
async getNewEndpoint(param1, param2) {
    return this.get(`/new-endpoint/${param1}`, { param2 }, true);
}

// 페이지 JS에서
const data = await API.getNewEndpoint(123, 'value');
```

토큰 갱신은 자동입니다. 추가 코드가 필요 없습니다.

### 사용 가능한 API 메서드

| 메서드 | 사용법 | 인증 헤더 |
|--------|-------|-----------|
| `API.get(endpoint, params, auth)` | GET 요청 | Yes (기본값) |
| `API.post(endpoint, data, auth)` | POST 요청 | Yes (기본값) |
| `API.put(endpoint, data, auth)` | PUT 요청 | Yes (기본값) |
| `API.delete(endpoint, auth)` | DELETE 요청 | Yes (기본값) |

예시:
```javascript
// 쿼리 파라미터를 포함한 GET
await API.get('/spaces', { page: 1, size: 15 });

// body를 포함한 POST
await API.post('/spaces', { name: 'New Space' });

// DELETE
await API.delete('/spaces/123');

// 공개 엔드포인트 (인증 없음)
await API.get('/public-data', {}, false);
```

## 백엔드 개발자용

### 필수 엔드포인트

**엔드포인트**: `POST /api/admin/refresh`

**요청**:
```json
{
  "refreshToken": "eyJhbGc..."
}
```

**성공 응답 (200 OK)**:
```json
{
  "accessToken": "eyJhbGc...",
  "refreshToken": "eyJhbGc..."  // Optional: 새 refresh token
}
```

**에러 응답**:
- `401 Unauthorized`: Refresh Token 만료/유효하지 않음 → 프론트엔드가 로그인 페이지로 리다이렉트
- `404 Not Found`: 사용자를 찾을 수 없음 → 프론트엔드가 로그인 페이지로 리다이렉트
- `500 Internal Server Error`: 서버 에러 → 프론트엔드가 에러 표시

### 통합 체크리스트

- [ ] `/api/admin/refresh` 엔드포인트 구현
- [ ] 요청 본문에서 Refresh Token 검증
- [ ] Admin user가 존재하는지 확인
- [ ] 새 Access Token 생성 (선택적으로 새 Refresh Token도)
- [ ] `accessToken` (및 `refreshToken`)을 포함한 JSON 반환
- [ ] Refresh Token이 만료/유효하지 않으면 401 반환
- [ ] Admin user를 찾을 수 없으면 404 반환

## 한눈에 보는 아키텍처

```
사용자 액션 → 비즈니스 로직 (spaces.js)
              ↓
          API.get() / API.post()
              ↓
          API.request()
              ↓
          fetch() → 서버
              ↓
          401 Unauthorized?
              ↓ YES
          Auth.refreshToken()
              ↓
          POST /api/admin/refresh
              ↓
          새 Access Token 받기
              ↓
          원래 요청 재시도
              ↓
          200 OK → 데이터 반환
```

**사용자가 보는 것**: 끊김 없는 경험, 에러 없음

```javascript

```

## 디버깅

### 콘솔 로그 확인

**정상 토큰 갱신**:
```
[API] 401 Unauthorized 감지: /api/admin/spaces
[API] Access Token 갱신 시도...
[Auth] Access Token 갱신 시도 중...
[Auth] Access Token이 성공적으로 갱신되었습니다.
[API] Access Token 갱신 완료. 원래 요청 재시도: /api/admin/spaces
```

**Refresh Token 만료**:
```
[API] 401 Unauthorized 감지: /api/admin/spaces
[Auth] Refresh Token이 만료되었습니다. 재로그인이 필요합니다.
[API] Token 갱신 실패: Refresh token expired
→ /admin/login으로 리다이렉트
```

### Network 탭 확인

**갱신 성공**:
```
GET  /api/admin/spaces     → 401
POST /api/admin/refresh    → 200
GET  /api/admin/spaces     → 200 (재시도)
```

**갱신 실패**:
```
GET  /api/admin/spaces     → 401
POST /api/admin/refresh    → 401
→ /admin/login으로 리다이렉트
```

### localStorage 확인

```javascript
// 브라우저 콘솔에서
console.log('Access Token:', Auth.getAccessToken());
console.log('Refresh Token:', Auth.getRefreshToken());
console.log('인증됨:', Auth.isAuthenticated());
```

## 보안 참고사항

### 토큰 저장
- `localStorage`에 저장됨 (`sessionStorage` 아님)
- 키: `admin_access_token`, `admin_refresh_token`
- 위험: XSS 공격으로 토큰 탈취 가능
- 완화: 모든 사용자 입력 검증, CSP 헤더 사용

### 토큰 로깅
- **실제 토큰 값을 절대 로그에 출력하지 않음**
- 작업 상태만 로그에 기록
- Network 탭에서 토큰 값이 보이는 것은 허용됨

### HTTPS
- 모든 토큰 전송은 반드시 HTTPS 사용
- HTTP의 토큰은 중간자 공격에 취약

## FAQ

### Q: 여러 요청이 동시에 401로 실패하면?
**A**: refresh token API 호출은 단 1회만 발생합니다. 모든 요청이 같은 갱신을 대기한 후 재시도합니다.

### Q: refresh API가 401을 반환하면?
**A**: 사용자가 자동으로 로그인 페이지로 리다이렉트됩니다. 토큰이 삭제됩니다. 무한 루프 없음.

### Q: Auth.refreshToken()을 직접 호출할 수 있나요?
**A**: 안 됩니다. `API.request()`가 401 감지 시 자동으로 호출합니다. 직접 호출하면 문제가 발생할 수 있습니다.

### Q: 새 어드민 페이지를 어떻게 추가하나요?
**A**:
1. 스크립트 로드: `auth.js` → `api.js` → `your-page.js`
2. 페이지에서 `API.get()`, `API.post()` 등 사용
3. 토큰 갱신이 자동으로 작동함

### Q: 토큰 갱신을 어떻게 테스트하나요?
**A**: 자세한 시나리오는 `테스트_가이드.md` 참조. 빠른 테스트:
1. 로그인
2. localStorage에서 Access Token 만료 (JWT exp 필드 변경)
3. 아무 액션 클릭
4. 로그인 페이지로 리다이렉트 없이 작동해야 함

### Q: 공개 API가 필요하면 (인증 없음)?
**A**: 세 번째 파라미터로 `false` 전달:
```javascript
await API.get('/public-endpoint', {}, false);
```

### Q: 토큰은 얼마나 유효한가요?
**A**: 백엔드에서 구성 가능. 일반적으로:
- Access Token: 15분
- Refresh Token: 7일

### Q: 모바일 앱에서도 작동하나요?
**A**: 아니요. 이것은 웹 어드민 패널 전용입니다. 모바일 앱은 다른 토큰 관리가 필요합니다.

## 흔한 실수

### 실수 1: API 래퍼 대신 직접 fetch 사용
```javascript
❌ const response = await fetch('/api/admin/spaces', {
    headers: { 'Authorization': `Bearer ${token}` }
});

✅ const data = await API.get('/spaces');
```

### 실수 2: 수동 401 처리
```javascript
❌ if (response.status === 401) {
    await Auth.refreshToken();
    return fetchAgain();
}

✅ // API.request()가 자동으로 처리합니다
```

### 실수 3: Auth.refreshToken() 직접 호출
```javascript
❌ if (Auth.isAccessTokenExpired()) {
    await Auth.refreshToken();
}

✅ // API.request()가 토큰 갱신을 자동으로 처리하도록 하세요
```

## 성능 고려사항

### 동시성 제어
- 여러 동시 401이 단 1회의 갱신만 트리거
- `tokenRefreshPromise` 캐시로 구현됨
- 모든 요청이 같은 갱신 Promise를 대기

### 요청 재시도
- 토큰 갱신 후 단 1회만 재시도
- 무한 루프 방지
- 내부적으로 `isRetry` 플래그 사용

### 토큰 만료 확인
- JWT 만료는 백엔드에서 확인 (안전)
- 프론트엔드가 토큰을 미리 갱신하지 않음
- 갱신은 401 에러에 반응하여 발생
